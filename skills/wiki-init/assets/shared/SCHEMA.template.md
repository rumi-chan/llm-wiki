# {{PROJECT}} team wiki: schema

This is the contract for the shared wiki in `docs/wiki/`. Every agent working in this repo
(Claude Code, Codex, or any other) reads it before touching the wiki. Humans read
`docs/wiki/README.md` instead.

- Wiki language: **{{LANGUAGE}}** (code, identifiers, paths and commands stay verbatim)
- Created: {{DATE}}
- The wiki is **derived from the code**. The code is the source of truth. When they disagree,
  the page is wrong.

## Roles

| Who | What they do with the wiki |
|---|---|
| Member using an agent | At the end of a task, the agent updates the pages affected by *this branch's* changes (workflow "Update for your change"). Optional, encouraged. |
| Member without an agent | Nothing required. May fix pages by hand, keeping the frontmatter. |
| Wiki maintainer (team leader) | Periodically runs the sync on `main`, which fixes drift, merges duplicates and regenerates the index, delivered as its own PR. The only one who writes `.sync-state`. |
| CI (`.github/workflows/wiki.yml`) | Checks every PR with `tools/wiki/wiki.mjs check` and comments. Warnings never block merging. |

## Layout

```
docs/wiki/
├── SCHEMA.md            this file
├── README.md            the rules, for humans
├── wiki.config.json     allowed page types and statuses (read by the check script)
├── index.md             GENERATED by `node tools/wiki/wiki.mjs build-index`; never edit by hand
├── .sync-state          last `main` commit the maintainer synced to; maintainer only
├── overview.md
├── modules/<code path>.md
├── concepts/<slug>.md
└── decisions/<YYYY-MM-DD>-<slug>.md
```

There is no `log.md`: `git log -- docs/wiki` is the log.

| Type | Path rule | What it holds |
|---|---|---|
| overview | `overview.md` | What the project is, how to build and run it, how the pieces fit |
| module | `modules/<code dir>.md` | One page per significant code directory |
| concept | `concepts/<slug>.md` | An idea needed to understand the code (protocol, algorithm, format) |
| decision | `decisions/<YYYY-MM-DD>-<slug>.md` | Why something is the way it is, alternatives considered |

### Deterministic paths (this is what prevents duplicate pages)

Two people documenting the same thing must end up editing **the same file**, so that git shows
a conflict instead of two pages silently coexisting.

- Module pages mirror the code path: the page for `src/payment/` is `modules/src/payment.md`.
- Concept slugs are the canonical English term in kebab-case, singular: `concepts/session-token.md`,
  not `concepts/tokens.md` or `concepts/auth-tokens-explained.md`. Put other names in `aliases`.
- Decisions use the date the decision was made, so concurrent decisions never collide.

## Page format

```yaml
---
title: Payment module
type: module
status: draft            # draft | verified | stale
summary: Checkout flow, payment provider adapters and refunds   # one line, shown in index.md
aliases: [billing, checkout]
sources:
  - src/payment/                         # a directory
  - src/payment/checkout.ts#createOrder  # file#symbol
updated: YYYY-MM-DD
---
```

- **Cite `path` or `path#symbol`, never line numbers or commit hashes.** Line numbers drift on
  every edit and commit hashes disappear after squash or rebase merges. A symbol that no longer
  exists is detected by the check script.
- `status: verified` only after the claims were checked against the code. Mark single unverified
  claims with `(unverified)`.
- **One sentence per line** (semantic line breaks). Git then merges per sentence, not per
  paragraph, which removes most conflicts.
- **Minimal edits.** Change only sentences that became wrong or are missing. Never reflow,
  reorder or restyle text you are not otherwise changing.
- One page = one concept. Link related pages with relative links (`[payment](../modules/src/payment.md)`).
- Never write secrets, tokens, credentials or personal data.

## Workflows

### Start of a session (every agent)

Read this file and `docs/wiki/index.md`. Use the wiki to orient yourself before reading lots of code.

### Answering questions

Read `index.md`, then the relevant pages, then check the cited code when the answer matters or the
page is `draft`/`stale`. Do not create pages just to file an answer unless the user asks.

### Update for your change (members using an agent)

Run at the end of a task, on the feature branch, before the PR is opened:

1. `node tools/wiki/wiki.mjs check --base origin/<default branch>` lists pages that cite files
   changed in this branch ("drift").
2. Update each listed page so it is true for this branch's code. Minimal edits.
3. If the branch adds something significant that no page covers (a new module directory, a new
   protocol), create the page at its deterministic path. Before creating, search for an existing
   page: read `index.md` and `rg -i "<term>" docs/wiki` (titles and `aliases`). Extend instead of
   duplicating.
4. **Do not** edit `index.md` or `.sync-state`. The maintainer's sync regenerates them.
5. Run the check again. Fix errors; warnings about pages you did not touch are fine.
6. Leave the wiki edits in the same branch as the code; commit them the way the user normally commits.

### Sync (maintainer only)

Done with the `wiki-sync` skill, on an up-to-date `main`:
diff `.sync-state..HEAD`, verify pages that authors already updated, fix pages that drifted,
merge duplicates (keep one page, move the other's names into `aliases`, fix links), run
`build-index` and `check`, write the new `.sync-state`, and open a `wiki: sync` PR.
Never push the sync straight to `main`.

### Merge conflicts inside `docs/wiki/`

Take either side. The wiki is derived from code, so nothing is lost: the next sync fixes it.
For `index.md`, take either side and run `node tools/wiki/wiki.mjs build-index`.
**Never hold back a code merge because of a wiki conflict.**

## Tooling

- `node tools/wiki/wiki.mjs build-index` regenerates `index.md` (maintainer / sync only).
- `node tools/wiki/wiki.mjs check` is a full check: frontmatter, links, sources, duplicates,
  secrets, orphans, stale index.
- `node tools/wiki/wiki.mjs check --base origin/main` is PR mode: pages changed in the branch,
  plus drift.
